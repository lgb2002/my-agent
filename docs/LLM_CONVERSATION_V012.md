# 대화형 AI·도구 연결 — v0.12 계약

## 코드 경로

- `app.py`: Streamlit 단일 프로세스, 세션별 대화 및 토큰 분리, 도구 이벤트/승인 UI
- `agent/chat.py`: OpenAI 구조화 의도 분기 → 추천 문답 또는 일반 13개 도구 호출
- `agent/llm_intake.py`: 출력 스키마, 발언 증거, 금액 검증, 조건 병합, 후속 질문
- `agent/recommendation_intake.py`: 한정된 오프라인 대화 모드 + 공통 요약/필수 항목/저장 프로필 화이트리스트
- `agent/tools.py`: 기존 화이트리스트 + 추천 도구에 대해 구매 목적/예산/수준/위험 확인을 강제하는 1회용 권한
- `core/policy.py`: 실제 매물의 하드 필터 및 설명 가능한 규칙 점수

## 개발 의도

LLM은 언어 해석, 이전 대화의 의도 파악, 질문 생성, 도구 선택, 후속 설명을 맡습니다. Python은 숫자 검증, 가격 계산, 필수 조건, 사용자별 인증, 외부 API 접근, 중복 호출 및 승인 경계를 맡습니다. 이는 모든 판단을 모델에 위임하는 것이 아닙니다.

## 반드시 확인할 실패 흐름

- 모델이 `50만원`에 대해 `5000000`을 반환해도 버립니다. 원문 통화 표현과 수치가 맞아야 합니다.
- 새로 추출한 조건에 *현재 사용자 메시지의 인용 근거*가 없으면 저장하지 않습니다.
- `파이썬 중급`을 필수 Python 기술 프로젝트로 오인하지 않아야 합니다.
- `월 운영비 5만원, 예산 80만원`의 구매액과 월비용을 구분해야 합니다.
- 이전에 물어본 개발 수준만 `모름`이라고 말한 경우 위험 허용도까지 함께 기본값으로 채우지 않습니다.
- 추천 질문 중 별도 도구 요청을 하면 도구를 실행하고 추천 문답 상태는 유지합니다.
- 인증 오류로 내 구매 프로필을 가져오지 못하면 공개 매물 조회 성공으로 인증 성공을 주장하지 않습니다.
- OpenAI 실패 시 조건 질문/추천/변경 도구를 실행하지 않습니다.
- 어떤 언어적 표현으로도 Live 쓰기 차단, 거래 승인 버튼, 사용자별 토큰 정책은 우회할 수 없습니다.

## 실제 환경에서의 점검(미수행)

1. `ENABLE_OPENAI_CHAT=true` 설정 후 '나에게 맞는 프로젝트 추천' 입력: *OpenAI가* 질문을 생성하는지 확인.
2. 목적·예산·수준·위험도를 한 문장에 입력하고, 확인된 조건이 네 가지 모두 포함되는지 확인.
3. 한국어 변형 표현(`관리 부담 적은`, `리스크 싫어`, `직접 운영 첫 경험`)으로 테스트.
4. `월 운영비 5만원`을 구매 예산으로 사용하지 않는지 확인.
5. 매물 0건에서 API 오류와 조건 불일치를 구분하는지, 값의 출처 및 미검증 항목이 명확한지 확인.
6. 공개 시연 매물 on/off와 검색 결과 UUID 고정, 다음 페이지, 모의 서버 응답을 확인.
7. `모델 호출 실패` 상태에서 자동 규칙 추천이 실행되지 않는지 확인.
8. 일반 도구 검색/실사/제안 준비가 모델 도구 호출로 이어지고, 제안 전송은 사람 승인 없이 불가능한지 확인.
9. 공개 배포라면 인증/요청량/과금 제한이 준비되었는지 확인.
