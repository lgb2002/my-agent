# v0.18.8 배포 · 대화 UX / 자동 저장

## 변경 내용

- 첫 화면: 기존 작업 중심 디자인과 API 정확성 원칙은 유지. 빈 대화에서 `st.chat_input`을 제목 바로 아래의 기본 행동으로 배치, 4개 빠른 시작 버튼은 두 번째 행동으로 간결하게 표시. 대화 시작 후에는 기존 작업/비교/실사 UI와 하단 입력창이 그대로 작동.
- 사이드바: `새 대화`, 제목 검색, 오늘/지난 7일/이전 그룹, 대화 전환·개별 삭제, 계정(하단). 9개 도구 이름은 계정의 접힌 `기능 안내`에 유지, 일반 DB 진단/개발자 메뉴는 표시하지 않음.
- 저장: OIDC + Broker를 통해 검증된 본인 계정으로 연결하고 에이전트 PostgreSQL을 사용할 수 있으면 `save_conversation()`을 자동 호출. 과거 `agent_chat_settings.auto_save` 값은 무시하되 테이블을 삭제하거나 변경하지 않음. 기존 수동 저장 대화는 동일 목록에서 조회. 대화가 없으면 비어 있는 초안만 유지.
- 삭제: 개별 삭제 유지, `대화 관리 → 전체 대화 삭제 → 전체 삭제 확인` 새로 추가. SQL은 `DELETE FROM agent_saved_conversations WHERE owner_key=?`만 실행. 타 계정 대화·사용자 구매 조건·작업 계획·거래 상태를 삭제하지 않음.
- 안전: 대화 텍스트와 제한된 도구 요약만 저장. 승인 카드/nonce, 도구 응답 원본, ZIP, 액세스 토큰 및 인증정보는 저장하지 않음. 저장 실패·비밀정보 탐지·용량 초과 시 현재 화면 기록은 유지하되 영구 저장은 되지 않을 수 있음.

## 배포 및 확인

1. v0.18.8 전체 ZIP을 기존 `my-agent` GitHub 저장소에 병합하고 커밋·푸시. `data/`, `.env`, `.venv`, 개인 Secrets 유지.
2. Streamlit Cloud 앱 재시작 (Replit 플랫폼 재게시, 추가 Supabase 키 및 DB 마이그레이션 불필요).
3. 새 대화에서 자연어 메시지 전송 후 새로고침, 다시 로그인, 별도 브라우저에서 대화 목록과 내용 복원 확인.
4. 다른 계정으로 로그인하여 다른 사용자의 기록이 보이지 않는지 확인.
5. 대화 하나 삭제 / 전체 삭제를 각자 확인하고, 구매 조건/작업 계획은 유지되는지 확인.
6. 모바일 폭에서 사이드바 열기와 첫 입력창, 4개 시작 버튼을 확인.

**주의:** 이전 버전에서 사용자가 자동 저장을 꺼 두었던 경우에도, v0.18.8부터 검증된 로그인 상태의 새 대화 내용은 기본 저장됩니다. 서비스의 개인정보처리방침과 보관/삭제 고지가 이 동작에 맞도록 운영자가 확인해야 합니다. 과거 기존 데이터는 자동 삭제하거나 외부로 옮기지 않습니다.

오프라인 테스트 성공은 실제 PostgreSQL 동시성 및 Streamlit Cloud 인증/저장 E2E 성공을 보장하지 않습니다.
