# ProjectAgain Agent v0.18.6 — 데이터베이스 접속 세분화 진단

v0.18.5 진단에서 DB 접속 단계에 `기타 데이터베이스 연결 오류`가 나타나는 경우 추가 정보가 필요하므로 아래 검사를 보완합니다.

- 연결 URI를 libpq 파서로 검사하고 URL 파서와 읽기 전용으로 비교합니다. 실제 주소, 사용자명, 비밀번호, 호스트는 결과에 표시되지 않습니다.
- PostgreSQL 연결 자체가 실패하면 드라이버 예외 종류를 **허용 목록의 이름만** 표시합니다. 예외 원문은 표시·기록하지 않습니다.
- 기존 오류 분류를 암호 인증/SCRAM, 연결 문자열 해석, 서버 연결 종료 등으로 확장합니다.
- DB 접속에서 원인이 구분되지 않은 경우에만 Supabase 데이터베이스 도메인의 DNS 조회와 TCP 포트 연결을 추가 확인합니다. 서버에 로그인하거나 데이터를 조회·변경하지 않습니다. 허용된 DNS 도메인은 `*.pooler.supabase.com`, `db.*.supabase.co`이고 포트는 5432/6543으로 제한합니다.
- DNS 또는 TCP 연결이 성공하더라도 PostgreSQL 인증 성공을 뜻하지 않습니다. 별도의 `SELECT 1`이 통과해야 최종 연결 성공입니다.
- 모든 진단은 기존처럼 ProjectAgain OIDC로 로그인한 사용자에게만 버튼을 제공하고, 30초 재실행 제한을 유지합니다.

## 결과 읽기

| 결과 | 우선 확인 대상 |
|---|---|
| 연결 문자열 해석 오류 | Supabase Connect의 원본 URI 및 인코딩 |
| DNS 접속 확인 실패 | Streamlit Cloud의 이름 조회/호스트 |
| TCP 접속 확인 실패 | 네트워크, 포트 및 Supabase 실행 상태 |
| DB 협상/인증 단계 확인 필요 | Supabase Pooler 접속 계정·비밀번호·TLS·서버 응답 |
| 정상 | Broker 권한 연결 API 및 DB CREATE 권한 확인 |

**중요:** 진단에서는 원본 오류 문자열과 데이터베이스 인증정보를 절대 출력하지 않습니다. 검사 결과만 공유할 수 있습니다. 실제 운영 서비스의 네트워크 접속 성공 여부는 Streamlit Cloud에서 검증해야 합니다.
