# v0.17.3 · 상태 기반 프로젝트 작업 공간 구현 및 검증

## 목적

대화를 없애거나 별도 관리자 대시보드를 만드는 것이 아니다. **사용자의 현재 작업에서 확인된 결과와 다음 행동**을 AI 설명보다 먼저 읽을 수 있도록, 동일한 채팅 흐름을 상태 기반으로 표현한다. 데이터의 출처는 ProjectAgain 플랫폼 API 하나이고, 내부 Mock 모드는 되살리지 않는다.

## 실제 화면 판단

`core/workspace_state.py`는 현재 브라우저의 **활성 대화 세션**에서 `pending`, `recommendation_intake`, 진행 중인 작업 계획, 마지막 도구 이벤트, 마지막 AI 답변을 순서대로 검사한다.

| 상태 | 표시 내용 | 제공 행동 |
|---|---|---|
| 첫 방문 | 기존 간결한 첫 화면과 4개 시작 행동 | 탐색, 맞춤 추천, 실사 준비, 기록 조회 |
| 매물 목록 | 실제 응답의 제목·가격·기술, 최대 15건을 8건+추가 영역으로 표시 | 목록에서 직접 선택하여 공개 정보 점검, 다음 페이지 |
| 추천 조건 확인 | 사용자가 입력한 목적·예산·기술·개발 수준·위험 허용도 | 인라인 수정 또는 대화로 여러 조건 보완 |
| 추천 결과 | 상위 3건 비교, 가격, 부합 근거, 미확인 위험 | 후보 상세·공개 정보 검토·차이 비교·재추천 |
| 공개 정보 점검 | 정적 검사에서 발견한 사항과 추가 확인 권장 | 미검증 항목 질문·다른 후보 탐색 |
| 제안 확인 | 기존 구매 제안 확인 카드와 플랫폼 승인 분리 | 직접 초안 제출, 상태 조회, 취소 |
| 작업 이어가기 | 실제 완료·대기·차단된 단계와 다음 행동 | 상태 재조회, 이어서 진행 또는 중단 |
| 일반 후속 질문 | **가장 최근 AI 답변**을 먼저 표시하고 이전 작업 결과는 펼쳐 열람 | 이어서 대화 |
| 계정 저장 대화 복원 | 안전하게 보관된 문장과 도구 요약만 표시 | 실제 플랫폼에서 새로 조회 |
| 시연 매물 필터 변경 | 이전 목록·추천을 변경된 필터의 결과로 표시하지 않음 | 새로운 API 목록 조회 |

**표시 우선순위:** 실제 사용자 확인이 남아 있는 제안 → 누락 정보 입력 → 최신 성공/실패 도구 결과 → 작업 상태 → 대화 응답 → 첫 방문. 이전 조회 뒤 새 AI 답변이 왔다면 새 답변이 우선이다.

## 보존된 안전 경계

- 추천 결과에서 새로운 프로젝트·가격·수익·검증 상태를 만들어내지 않는다. 점수는 상대적 판단 보조임을 유지한다.
- 목록의 `id`, 추천 결과의 `listing_id`는 UUID인지 확인한 뒤에만 후속 공개 정보 점검 버튼에 연결한다.
- 시연 매물 포함 옵션은 ProjectAgain API 필터다. 로컬 가짜 매물을 조회하지 않는다.
- 사용자 로그인·권한·OpenAI 사용량·PostgreSQL 저장·동의·거래 승인·실제 거래 실행은 v0.17.2 정책을 유지한다.
- 작업의 `WAITING_APPROVAL`, `PARTIAL`, `BLOCKED`를 완료된 단계 수에 포함하지 않는다.
- 플랫폼에 초안을 제출했더라도 승인·거래 완료·결제·저작권 이전을 주장하지 않는다.
- 보관된 대화에서는 원본 API 응답·승인 카드가 제거되어 있으므로, 보관된 도구 요약을 최신 정보처럼 사용하지 않는다.
- 추천 조건을 바꿔도 **기존 추천은 당시 조건으로 표시**한다. 새 조건은 다시 추천할 때 적용된다.

## UI 원칙과 제한

- 결과가 화면의 중심이고, 과거 말풍선/도구 JSON은 기본 닫힌 **이전 대화 및 도구 실행 기록**에서 확인한다. 기록은 삭제되거나 80개로 잘리지 않는다.
- 하나의 페이지 스크롤을 유지한다. 고정 높이 540px 채팅창을 복구하지 않는다.
- 후속 작업은 작업 화면에 붙은 작은 행동 버튼으로 제공하며, 키보드·터치 조작은 Streamlit의 네이티브 위젯을 유지한다.
- 데스크톱과 모바일 너비별 CSS 정적 검증은 Python Playwright/Chromium으로 수행하며, **Streamlit 실기동을 검증하는 것은 아니다.**

## 검증

`python -m scripts.run_tests` — 전체 191개 테스트 통과 / 실패 0건.

`python -m scripts.verify_workbench_static` — 정적 CSS를 적용한 예시 레이아웃을 320, 360, 390, 768, 1280px에서 확인, 전체 문서의 가로 넘침 없음. 390px/1280px 이미지는 `docs/workbench_static_*px_v0173.png`에 기록. 이것은 정적 HTML 검증이며 Streamlit DOM 렌더링, 실제 OpenAI 호출, Replit API 통신은 검증하지 않았다.

## 배포 후 확인할 실제 사용자 흐름

1. 첫 접속에서 매물 목록 열기 → 9개 도구 중 실제 매물 검색 응답 확인 → 특정 행 선택 → 공개 정보 점검.
2. 추천 조건을 자연어로 여러 개 입력 → 추천 표 3건 및 위험·적합 근거 확인 → 추가 질문 후 **새 답변이 먼저 보이고 이전 표는 펼침 영역에 남는지** 확인.
3. 추천 조건 변경 → 이전 결과의 조건이 바뀌지 않는지 확인 → 재추천 뒤 새 조건 반영.
4. `시연 매물 포함`을 해제 → 예전 매물이 새 필터 결과인 것처럼 표시되지 않는지 확인.
5. 다단계 작업 중 추가 질문·금액 확인 → 정적 자료 검사 및 실제 제안 초안 확인 → 초안 접수와 승인·실행 구분 확인.
6. 이전 대화 보관함에서 대화 전환·재진입 → 승인 카드 자동 복원 금지 → 인증 계정의 동의 저장·복원·삭제 확인.
7. PC 및 실제 스마트폰에서 스크롤/키보드/표 읽기/사이드바/채팅 입력/승인 버튼을 직접 테스트.
