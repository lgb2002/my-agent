# ProjectAgain Agent v0.15 — 연동 및 검증 노트

## 구현 사실과 확인되지 않은 조건

**코드에서 확인됨:** 기존 13개 ToolDispatcher 도구 유지, Mock/Live GET 유지, 사용자 조건과 UUID/작업 단계 요약, 7차원 위험 원본 상태, Streamlit 추천 카드와 후속 공개 정보 검토 버튼, 원격 액션 ID의 안전한 체크포인트 및 상태 조회·복원, 저장소 health check, 사람 버튼 전용 Live 초안 API 함수.

**모의 객체로 검증됨:** 사용자가 누른 버튼에서만 초안 함수 호출, 본인 토큰·`offer:draft` 권한·계정 동일성 검사, 요청 키 생성, 일반 Live POST 차단, 저장소 임시 여부, 위험 미확인 처리, 실제 후보 기반 비교.

**현 환경에서 미검증:** Replit 플랫폼 v0.13 실제 POST `/api/v1/agent-actions`의 request schema, SHA-256 canonical JSON 규격, 멱등 처리, 권한 scope 노출, 승인 액션 응답 형태, Streamlit Cloud 실제 POST·GET, 사용자별 PostgreSQL 실연결·재시작 뒤 복구, 유료 OpenAI 호출, 실제 화면 렌더링.

## 초안 연동을 활성화하기 전 반드시 확인할 것

1. v0.13 실제 `openapi.json`에서 `POST /api/v1/agent-actions`의 요청 필드와 `SUBMIT_OFFER`의 `proposed_payload`를 비교. 현재 코드의 필드가 다르면 양측 계약을 맞춘 뒤 활성화.
2. `Idempotency-Key`가 DB 유니크 제약과 연결되어 있는지, 같은 키 재호출과 다른 본문 재호출에서 중복 액션 생성이 차단되는지 플랫폼 테스트.
3. 사용자별 위임 토큰의 `offer:draft`가 `/auth/me`에서 확인되는지, 판매자 본인 매물 제안과 토큰 만료에서 403/401 반환하는지 확인.
4. 본인의 Streamlit 입력에서 초안 확인 버튼을 눌러 `PENDING_APPROVAL` 생성. Replit 웹의 거래 업무실에서만 승인/거절, 별도 실행이 이뤄지는지 확인. 에이전트는 상태 GET만 허용.
5. 응답 유실/네트워크 타임아웃 테스트: 에이전트는 같은 초안을 자동 재제출하지 않고 성공 여부 불명으로 표시. 사용자가 플랫폼에서 기존 초안을 먼저 확인.
6. 보안: 공용 `MARKETPLACE_API_KEY` 미사용, 사용자별 위임 토큰 UI에서 노출 금지, URL/DB URL·키 로그 비노출.

## 추천 및 기억 실제 사용자 검증

- 동일 예산에서 LOW와 MEDIUM을 비교하되 LOW에 미검증 항목이 있는 경우 후보 제외 사유와 상태가 명확한지 확인.
- 정성 선호를 주면서 여러 조건을 한 번에 입력하고, 모델이 근거 없는 매출·권리 확인을 만들지 않는지 검사.
- 이전 조건·후보 1번 UUID를 유지한 상태에서 10회 이상 대화 후 다시 질문. 세션 요약이 맥락을 이어주는지, 예전 발언을 무단으로 최종 조건처럼 쓰지 않는지 확인.
- 복합 계획의 단계별 성공/실패/중단/재개, 최대 3회 재시도 상한, 이전 완료 단계 중복 실행 여부 검사.
- Streamlit Cloud에 실제 `AGENT_STATE_DATABASE_URL`을 설정하고 계정 A/B 격리, SQLite 비영속 경고, 재배포 이후 저장·복원까지 별도로 검증.
- 추천 카드의 데스크톱·모바일 정렬과 접기 영역 스크롤을 실제 화면에서 시각적으로 확인.

## 알려진 범위

- 장기 업무 엔진은 모든 13개 도구에 대한 임의의 범용 플래너가 아니라 추천부터 이어지는 허용된 다단계 경로입니다.
- 사람 승인 흐름은 플랫폼 API 계약에 맞춰 활성화하기 전까지 **Live 초안 제출도 기본 차단**입니다. 이 버전에서 제안 전송, 승인, 실제 거래 변경을 자동화하지 않습니다.
- 무료 공개 OpenAI 사용량 제한·호출 비용 상한, 대형 파일 격리 실사 등은 이번 범위 밖입니다.
