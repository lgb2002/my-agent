# v0.17.1 A/B/C 화면 개선 검증

## 범위

1. A — 진행률은 실제 `COMPLETED` 상태만 합산하며 작업 완료/승인 대기/실제 거래 완료를 구분한다.
2. B — 사용자에게 표시되는 추천 데이터는 기존 API 추천 결과의 범위와 순서 그대로 비교한다. 매물명·가격·적합 이유·주요 위험을 비교하고 후보별 상세·검토 행동으로 이어간다.
3. C — 채팅 기록에 독립적인 540px 세로 스크롤을 부여하지 않는다. 대화가 길어지면 문서 스크롤만 사용하고, 작업 계획은 축약 요약과 사용자가 여는 상세 영역으로 분리한다.

## 구현 구조

- `core/ui_presentation.py`: UI와 분리한 상태 해석(`workflow_view`)·추천 자료 변환(`recommendation_view`). 서버 연동, 거래 실행, 사용자 데이터 변경을 수행하지 않는다.
- `app.py`: 현재 작업 요약·추천 비교표·후보 상세·명시적 후속 행동, 도구 이벤트의 범위별 상태 문구. 기존 같은 채팅/도구 실행 파이프라인을 사용한다.
- `assets/style.css`: 콘텐츠 최대폭, 간결한 작업 요약, 비교표의 좁은 화면 처리, 단일 페이지 스크롤의 기본 구조.
- `DESIGN.md`: 사용자 결과/상태/근거/다음 행동 중심의 지속적인 디자인 원칙.

## 자동 검증 범위

- 혼합 상태 `COMPLETED/PARTIAL/BLOCKED/WAITING_APPROVAL/SKIPPED`가 100%로 표시되지 않는지 검사한다.
- 승인 대기만 존재하거나 비어 있는 작업, 가격 재확인, 목표 부분 완료·완료 상태를 구분한다.
- 실제 결과에 포함되지 않은 매물을 생성하지 않는지, 결손 근거를 확인됨으로 표시하지 않는지 검사한다.
- 세 후보까지만 비교하고 실제 순위 및 ID를 보존하는지 검사한다.
- 고정 높이 채팅 컨테이너가 재도입되지 않는지, 승인·토큰·후속 도구 경로가 유지되는지 정적 검사한다.

## 미검증 및 배포 후 확인 사항

- 이 개발 환경에는 Streamlit이 설치되어 있지 않으므로 실제 Streamlit 브라우저 렌더링은 확인하지 않았다.
- Streamlit Cloud 데스크톱(넓은 창), 모바일(360–390px)에서 세로/가로 스크롤, 비교표, 첫/마지막 메시지, 상태 영역과 입력창 겹침을 확인해야 한다.
- 실제 OpenAI·Replit API·Supabase PostgreSQL 호출은 이번 UI 변경의 테스트 범위에 포함되지 않는다.
- 작업 상태와 추천 순위는 기존 정책/도구의 반환을 시각화하는 것이지, 별도의 실거래 위험 인증이 아니다.
