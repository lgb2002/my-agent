# ProjectAgain Agent v0.18.5 — 로그인 저장소 안전 진단

## 목적

Streamlit Cloud에서 `로그인 저장소 연결에 실패했어요.`라는 안내가 나올 때, 서버가 DB 접속 오류 원문과 비밀 접속 문자열을 브라우저에 보이지 않게 유지하면서 운영자가 실패 원인을 좁힐 수 있도록 합니다.

## 사용 방법

1. `ProjectAgain 계정으로 로그인`으로 Streamlit 기본 OIDC 브라우저 로그인에 성공합니다.
2. 왼쪽 계정 영역에 `로그인 저장소 연결에 실패했어요.`가 나타나면 **로그인 저장소 오류 진단**을 펼칩니다.
3. **DB 연결 진단 실행**을 클릭합니다. 안전을 위해 동일 Streamlit 세션에서 30초 안에 중복 실행할 수 없습니다.
4. 결과의 **확인 단계 / 분류 / SQLSTATE(표시되는 경우) / 조치 안내**만 확인합니다. 원본 DB 오류와 연결 문자열은 표시하지 않습니다.
5. 원인을 확인한 뒤 Streamlit Cloud Secrets를 수정하고 앱을 재시작합니다. 정상적으로 연결되면 진단 패널은 자동으로 사라집니다.

### 진단 대상

- `AGENT_STATE_DATABASE_URL` **실제 적용값** (`core/runtime_secrets.py`의 환경변수 우선순위를 그대로 따릅니다)
- Streamlit Secrets와 실행 환경변수 값이 서로 다를 때, 주소를 표시하지 않고 불일치 여부만 표시
- `psycopg` 드라이버 로딩
- 기존 BrokerStore와 동일한 5초 제한 시간 및 TLS 강제 설정으로 PostgreSQL 연결
- 읽기 전용 `SELECT 1` 실행
- 읽기 전용 `SELECT has_schema_privilege(current_user, 'public', 'CREATE')` 권한 확인 (테이블/사용자 데이터 수정 없음)

**오류 분류:** 인증 실패, Pooler 사용자 식별 오류, DNS 조회, 네트워크, 연결 시간 초과, TLS, 연결 수 한도, SQLSTATE, DB/드라이버 설정 오류 등. SQLSTATE가 없으면 표시하지 않습니다. 실제 DB 호출에 이르지 못하면 Supabase 쪽 로그에는 관련 기록이 없을 수 있습니다.

## 개인정보·운영 안전

- 기존 OIDC 로그인 이후에만 진단 UI가 나타나며, 저장소 오류가 없으면 버튼은 표시하지 않습니다.
- 진단 실행은 **사용자가 직접 버튼을 클릭했을 때만** 수행됩니다. 백그라운드 검사 없음.
- 진단 코드가 제공하는 결과는 허용된 분류 문자열, SQLSTATE 형식 코드 및 Boolean뿐입니다. 예외 메시지, 연결 URI, 사용자명, 비밀번호, 호스트, OAuth 세션, Bearer Token을 화면·로그·파일에 출력하지 않습니다.
- SELECT 외에 `CREATE`, `INSERT`, `UPDATE`, `DELETE`를 실행하지 않습니다. 별도의 PostgreSQL 계정/DB 생성이 필요하지 않습니다.
- 테스트의 연결 객체는 모의 구현입니다. 실제 Supabase 접속 성공을 보장하지 않습니다.
- 진단으로는 **DB 접속 상태**를 알 수 있지만 플랫폼 OAuth Broker API 또는 실제 권한 동의 기능 전체의 성공을 보장하지 않습니다.

## 배포

기존 v0.18.4 전체 프로젝트에 이 버전 전체 ZIP을 반영하고 GitHub에 커밋·푸시하면 됩니다. Secrets 값을 재발급하거나 `.env`/`.venv`/`data/`를 덮어쓰지 마세요. 기존 `requirements.txt` 항목 유지. 이 버전은 의존성을 추가하지 않았습니다.

서버 오류 분류 결과만 공유하면 되며 **실제 DB URL, 비밀번호, 인증 토큰, 원본 연결 오류를 공유하지 마세요.**
