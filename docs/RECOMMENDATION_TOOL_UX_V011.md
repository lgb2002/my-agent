# 추천 조건 인식·도구 노출 개선 (v0.11)

## 관찰된 문제와 원인

- v0.10: `SHOW_DEVELOPER_TOOLS=false`라면 전체 도구 목록을 볼 수 없었고, 첫 요청 이후에는 시작 버튼도 사라졌습니다. 실행 도구의 상태는 접힌 결과 상세에서만 확인할 수 있었습니다.
- v0.10: 추천 조건 추출에서 문장 공백을 제거해 `중급이고 위험`을 `중급이고위험`으로 바꾸면 `고위험`이 잘못 감지되었습니다. `위험 낮게`, `리스크 적은` 등의 일상 표현을 인식하지 못해 같은 질문을 반복할 수 있었습니다.
- v0.10: 구매 예산과 월 운영비가 동시에 언급될 때 마지막 금액으로 예산이 덮어써질 수 있었습니다.

## 반영

1. **항상 열 수 있는 도구 목록**: 사이드바에서 모든 13개 등록 도구 이름을 확인할 수 있습니다. 기본은 접힘. Live에서 거래 변경을 실행할 수 없다는 안내는 그대로 표시합니다.
2. **대화 중 바로가기**: 매물 검색, 맞춤 추천, 최근 작업. 클릭 시 별도 실행 권한을 부여하지 않고 기존 사용자 입력 파이프라인을 호출합니다. 추천 조건 수집 중에는 추천 버튼을 비활성화해 흐름을 덮어쓰지 않습니다.
3. **도구 실행 상태**: AI 답변 아래 실행 도구의 이름과 성공/확인 필요를 즉시 표시하고, JSON 등 상세는 요청할 때 열어 확인합니다.
4. **한 메시지의 여러 조건 추출**: 목적, 예산, 개발 수준, 위험 허용, 기술, 유형, 월 운영비를 독립적으로 추출합니다. 정보가 부족하면 이미 수집한 조건을 함께 보여주고 나머지만 묻습니다.
5. **추천 직전 조건 확인성**: 어떤 조건이 실제 추천 도구에 전달되었는지 결과 상단에 표시합니다. 과도한 추측을 막기 위해 불명확한 조건은 묻거나 명시적인 생략 답변만 기본값으로 처리합니다.
6. **기존 승인·권한 경계 유지**: `ToolDispatcher` 화이트리스트 및 Live GET-only, 개별 거래 승인 버튼을 수정하지 않았습니다.

## 확인 시나리오

- `맞춤 추천해줘` → `수익 목적이고 50만원 이하, 파이썬 중급이고 위험은 적은 게 좋아` → 추가 질문 없이 추천 실행, 위험 허용이 LOW인지 확인
- `맞춤 추천해줘` → `예산 80만원이고 월 운영비 5만원, 수익 목적, 초보, 리스크 낮게` → 예산 800,000원, 월비용 50,000원으로 분리
- `맞춤 추천해줘` → `50만원이고 파이썬 중급이야` → 확인한 조건이 표시되고 누락된 구매 목적부터 질문
- `추천해줘` → `수익용` → `50만원` → `초급` → `낮게` → 네 답변을 조합하여 한 번만 추천 도구 실행
- 매물 검색 도구 실행 후 모든 대화에서 도구 이름/결과 표식이 보이는지 확인
- 채팅을 몇 번 주고받아도 사이드바에서 전체 도구 목록을 열 수 있는지 확인

## 미검증

- 이번 작업 환경에는 Streamlit 1.67.0 런타임이 없어 Windows/Streamlit Cloud 실제 브라우저 화면을 렌더링하지 못했습니다.
- 위임 토큰, OpenAI 유료 호출, 실제 Replit HTTPS 연동은 이번 변경에서 실통신 검증하지 않았습니다.
- 규칙 기반 언어 인식은 모든 자유로운 표현을 포괄하지 않습니다. 인식되지 않는 표현은 구체적인 실제 입력 문장에 맞춰 회귀 테스트로 추가해야 합니다.
