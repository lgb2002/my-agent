# v0.17.2 대화·상태·반응형 검증 기록

## 브라우저 보관과 계정 보관의 차이

1. 기본 대화 보관함은 `st.session_state` 범위이며 같은 Streamlit 세션에서 새 대화, 이전 대화 재진입 및 삭제를 지원합니다. **다른 브라우저/재접속/서버 재배포를 넘어 영속성을 보장하지 않습니다.**
2. 본인 위임 토큰이 `/auth/me`에서 검증되어 확인된 owner만 별도의 `agent_saved_conversations` 테이블을 이용할 수 있습니다. '대화 장기 보관' 동의 + **명시적인 저장 버튼** 이후에만 서버 저장합니다. 서버 계정별 접근은 salted credential이 아니라 검증 사용자 ID + 플랫폼 URL의 해시를 사용합니다.
3. 저장 시 사용자/AI 텍스트 및 도구명·요약·성공 여부만 보관합니다. 원본 API JSON/추천 카드 세부 객체/워크플로 상태/트랜잭션 승인 nonce를 저장하지 않습니다. 대화 복원 시 원시 근거 카드가 비어 있음을 표시하고, 최신 데이터는 플랫폼 재조회를 안내합니다. `contains_obvious_secret`는 일부 알려진 자격증명 패턴만 확인하므로 **모든 민감정보를 자동 제거하는 기술은 아닙니다.** 개인정보가 포함된 대화의 장기 저장은 사용자 판단과 운영 보안 정책이 필요합니다.
4. 대화 ID는 임의 UUID4이고 DB owner는 서버에서 확인한 ID만 허용합니다. 다른 계정의 대화 조회/삭제는 불가합니다. 로컬 보관본과 DB에 저장된 보관본은 별개이므로 삭제도 별개입니다.

## UI/UX 원칙 검증

| 시나리오 | 기대 결과 | 검증 |
|---|---|---|
| 새 대화 시작 | 이전 대화와 컨텍스트가 삭제되지 않음 | 자동 테스트 |
| 다른 대화 재진입 | 이전 메시지/매물 문맥 복구, 과거 승인 카드는 재활성화 안 함 | 자동 테스트 |
| 동의 후 서버 저장/복원 | 대화 요약 보관, 원본 데이터·pending 복원 금지 | SQLite 단위 테스트 |
| 계정 A vs B | 대화 기록 교차 조회/삭제 차단 | SQLite 단위 테스트 |
| 도구 응답 성공 | 실제 거래·안전 인증 성공으로 표시하지 않음 | 자동 테스트 |
| 기능 바로가기 | 최근 매물 UUID가 확인된 경우에만 직접 검토 표시 | 자동 테스트 |
| 첫 화면 실사 | 매물 검색과 독립적인 설명 안내 | 자동 테스트 |
| 조건 요약/수정 | 다른 대화 조건을 변경하지 않고 이후 추천부터 적용 | 정적 코드 검증, 실화면 미검증 |
| 구매 제안 확인 | 금액/대상/단계/제출 여부 분리 | 정적 코드 검증, 실화면 미검증 |
| 320~1280px | 가상 DOM의 페이지 전체 가로 넘침 없음, 표 자체는 가로 스크롤 | Chromium 정적 CSS 검증 |

## 실제 배포 전 필수 검증 (아직 미완료)

- Streamlit Cloud에서 새 대화 후 100개 이상 메시지 재진입/새로 고침/다른 탭/브라우저 세션 테스트
- 계정 A/B 실제 토큰으로 저장·삭제·재접속·토큰 갱신 시 사용자 분리 검증
- 실 PostgreSQL 연결과 DB 오류·저장 용량·중복 저장 테스트
- OpenAI 실제 대화에서 저장된 추천 조건 수정을 명령했을 때 문맥 일치 확인
- Windows 데스크톱/Android Chrome/iPhone Safari 또는 에뮬레이터에서 키보드, 포커스, 스크롤, 세 후보 표, 승인 카드 360~390px 터치 동작 확인
- ProjectAgain 플랫폼 초안 `offer:draft` 권한 및 실제 API 계약 확인. 실거래 승인과 실행은 계속 플랫폼에서만 처리

**주의:** `scripts/verify_responsive_static.py`는 Streamlit 서버를 실행하지 않습니다. Streamlit DOM과 비슷한 마크업에 동일 CSS를 적용한 시각적 smoke test입니다. 화면 캡처 5장은 실제 배포 화면이라고 주장할 수 없습니다.
