# 추천의 조건·근거·위험 평가 — v0.13

## 이번 변경의 범위

**A. 의미 검증**: OpenAI의 구조화 추출 결과를 그대로 받아들이지 않는다. 각 값에 가장 최근 사용자 메시지의 정확한 인용이 필요하고, 개발 수준·위험 허용도는 해당 인용의 의미와 값이 모순되지 않아야 한다. '초보' → ADVANCED, '위험을 낮게' → HIGH 등을 차단한다. 명확한 의미를 확인하기 어려운 문장은 임의로 채우지 않고 추가 질문한다. 구매 목적은 직접적인 범주 반전 여부를 확인한다. 구매 예산/월 운영비는 각각 **숫자 하나가 있는 좁은 인용**으로 원화 환산을 검증한다. 기술에 대한 능력 진술을 곧바로 필수 기술 선호로 해석하지 않는다.

이 의미 검사는 포괄적인 자연어 정답 판별기가 아니다. 기초적인 명시 표현에만 엄격하게 적용하는 **모순 방지·보수적 보류 장치**다. 낯선 표현에서는 사용자에게 추가 확인해야 한다.

**B. 정성적 선호 활용**: '관리 쉬운', '자동화가 있는', '인수 후 유지보수가 단순한' 등 사용자가 제시한 선호를 최대 다섯 개까지 추천 도구에 전달한다. 서버에서 먼저 예산·기술·유형·위험 기준으로 후보를 필터링한 뒤, OpenAI가 켜져 있으면 상위 최대 열 개 후보의 **공개 판매자 정보만** 비교한다. 한 번의 Structured Outputs 호출로 선호별 `MATCH`, `MISMATCH`, `UNKNOWN`을 판단한다.

- 인용 구절이 그 후보의 원본 공개 정보에 실제로 포함되지 않으면 해당 판단은 버린다.
- 근거가 있는 정성 일치에는 최대 +10점, 불일치는 -10점(전체 보정 최대 ±20점), 자료 부족에는 0점.
- AI는 **예산·기술 필수 조건·저위험 제외 후보를 복원할 수 없다**. 점수 보정 대상은 1차 적격 후보뿐이다.
- 정성 평가 오류·미지원·근거 부족 시에는 임의의 긍정 점수를 주지 않고 기존 규칙 후보를 유지하며 '정성 평가 미완료/근거 부족'을 밝힌다.
- 모델 판단은 **판매자 공개 자료의 해석**이지, 실제 수익·안전·구동·법률적 권리 검증 결과가 아니다. 규칙 기반 `base_score`와 AI 보정 `qualitative_adjustment`를 따로 노출한다.

**C. 위험 상태**: 기술, 운영비, 수익 근거, 권리, 보안, 인수인계, 검사 상태를 구분한다. 항목별로 `ISSUE`, `UNKNOWN`, `SELLER_REPORTED`, 제한적으로 `STATIC_CHECKED` 또는 `EXECUTION_CHECKED` 등 출처/검증 수준을 명시한다. 확인되지 않은 사항을 안전하다고 주장하지 않는다.

위험 허용도가 `LOW`인 경우 다음과 같은 매물은 추천 대상으로 넣지 않는다.

1. 플랫폼에 정적/실행 검사 자료 표시가 없는 경우 (`UNVERIFIED`, 빈 값 등)
2. 초급·입문 사용자에 비해 Kubernetes·SaaS 등의 기술 복잡도가 지나치게 높은 경우
3. 월 운영비 상한이 정해졌는데 운영비 자료가 없는 경우
4. 권리 범위가 미확인되었거나 재판매 목적과 양도 권한이 불일치하는 경우
5. 공개적으로 고지된 심각한 결함(보안 노출·권리 분쟁·구동 불가 등)이 있는 경우

**유의:** 플랫폼 `STATIC_CHECKED`라는 표시만으로 실행·보안·법적 권리와 인수인계 안전을 검증했다고 보지 않는다. 등록된 매물이 모두 `UNVERIFIED`라면 `LOW` 추천 결과는 0건일 수 있으며, 이는 기능 실패가 아니라 충분한 검증 근거가 없다는 뜻이다. 위험 판단은 별도의 실제 실사를 대신하지 않는다. 사용자가 명시적으로 조건을 변경하지 않는 한 위험 기준을 조용히 완화하지 않는다.

## 데이터·도구 흐름

1. 사용자 입력 → OpenAI 구조화 조건 추출 → 인용·의미·원화 금액 검증
2. 확인된 조건 → 기존 `recommend_listings` 도구(13개 도구 목록 자체는 변경 없음)
3. 기존 ProjectAgain `GET /api/v1/listings` 조회 → Python 필수 조건·위험 평가 → 적격 후보 최대 10개 준비
4. `qualitative_preferences`가 있고 OpenAI가 활성화되어 있다면 **추가 OpenAI 1회**로 공개 근거 기반 정성 검토 → 최종 상위 3개
5. 사용자에게 적용된 기준, 제외된 이유(0건일 때), 추천 근거와 불확실성 노출. 각 모델 평가는 판매자 고지 자료 기반 추정임을 분명히 한다.

추천 작업은 **Streamlit 내부 저장 작업**이며 Replit 플랫폼에 거래 변경을 보내지 않는다. Live 모드는 계속 GET 조회 전용이고 구매 제안/승인은 바뀌지 않았다.

## 검증

- 기존 v0.12 테스트 97건과 A/B/C 전용 회귀 테스트 24건을 단일 프로세스에서 실행.
- OpenAI 실제 API 호출 없이 구조화 응답과 매물 데이터를 통제하여 검사.
- 독립적으로 확인할 추가 항목: 한국어 자유 표현에서 모델의 구조화 응답 품질, 낮은 위험 조건에서 후보 감소에 대한 사용자 이해, Streamlit Community Cloud에서 두 번의 모델 호출과 화면 응답 시간, Replit 실제 매물 필드의 누락/상태값.

전체 숫자는 `docs/test_results.json`을 참고한다. 테스트 통과는 실제 Replit/OpenAI/브라우저 통합 성공을 의미하지 않는다.
