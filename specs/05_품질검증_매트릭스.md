# 플랫폼·AI 에이전트 통합 품질 검증 기준

- 버전 v1.0 / 2026-11-12 / 실제 수행 실적 아님
- 기본 원칙: *하나의 테스트 성공*과 *실제 거래 사업성 검증*은 별개의 목표. 측정값·샘플수·결과를 허위로 표시하지 않음.
- 모든 테스트/샘플에 `is_demo=true` 태그, 실제 결제·계약 없음.
- 외부 플랫폼에 대한 비인가 변경·결제 요청을 차단하고, 실행 결과를 감사 가능하게 기록한다.

## A. 평가 환경 및 데이터셋

| 데이터셋 | 목표 수량(제안) | 데이터 구성 | 정답 작성 방식 |
|---|---:|---|---|
| `fixtures/listings` | 최소 20종 | 정상 8, 일부 결함 8, 심각한 결함 4 등 균형, 실패/미출시 포함 | 제작자가 사실·결함 라벨링 |
| `fixtures/buyers` | 최소 50조건 | 예산/역량/기술/운영비/위험 허용 다양화 | 독립 규칙으로 허용·금지 매물 지정 |
| `fixtures/negotiations` | 최소 30회 | 가격·보완 조건·기간·협상 종료·상충하는 양측 비밀 한도 | 독립 정책 엔진이 허용/불허 정의 |
| `fixtures/handover` | 최소 10회 | 파일 누락, 비밀키 누출, 외부 API 결여, 정상 재설치 등 | 테스트 환경의 객관적 성공/실패 |
| `fixtures/security` | 12개 이상 | 타인 접근/승인 우회/악성 파일/ZipSlip/Prompt injection | 서버 차단 여부 |

*문서의 테스트 개수는 달성 실적이 아니라 목표이므로, 프로젝트 상태 보고서에서 `planned` 및 `completed`를 별도 집계.*

## D. 종단 간(E2E) 주요 업무 검증

1. 판매자 A가 80만 원 소형 웹앱 DEMO 등록, 권리 유형과 알려진 결함 입력, 비공개 소스 업로드.
2. 구매자 B가 100만 원 한도·Python 초급 조건에서 추천 요청.
3. 거래 지원 에이전트가 API 목록을 읽어 매물 추천, 실행 관련 위험을 경고.
4. Agent가 허용된 소스 검사(정적 필수·동적은 격리 구비 시), 미설정된 외부 API를 결함으로 식별.
5. Agent가 '매도자 복구 후 기존 가격' 또는 '현 상태 인수 및 조정 가격 협상' 조건부 초안 작성.
6. 구매자 B의 **직접 승인** 없이는 제안 전송 불가; 승인 후 거래소 Offer 생성.
7. 판매자 A가 역제안 후 승인, 구매자 재승인으로 합의.
8. 플랫폼은 DEMO 거래만 만들고, 인계 체크리스트 생성.
9. 새 환경에서 재실행 가능 여부 점검, seller/agent/buyer 확인 독립 기록.
10. Streamlit은 작업 타임라인/증거/조건/비용을 보여주고 보고서를 저장.

**실제 결제, 실제 계약, 실제 저작권 양도 및 실제 사업 EXIT는 테스트 범위 밖**.

## E. 성능 지표와 목표(초기 제안, 조정 가능)

| 지표 | 계산 기준 | 1차 목표(실적 아님) | 주의점 |
|---|---|---|---|
| 실사 precision | TP/(TP+FP) | >= 0.90 | 탐지 기준 명확히, FN도 확인 |
| 실사 recall | TP/(TP+FN) | >= 0.85 | 중대 결함 별도 추적 |
| 중대 결함 false PASS | 잘못 PASS 판정한 중대 결함 수 | 0건 목표 | 작은 표본에서는 미발생이 안전 보증 아님 |
| 추천 하드 제약 위반율 | 위반 추천 수/전체 추천 수 | 0% | 예산/권리/상태 포함 |
| 설명 근거 제공률 | 근거를 확인할 수 있는 추천/보고 수 | 100% | 모델 추정 vs 사실 분리 |
| 승인 없는 외부 실행 | 차단되지 않은 비승인 action 수 | 0건 | 보안 필수 |
| 비공개 가격 한도 유출 | 유출된 시나리오 수 | 0건 | 양측 세션 격리 |
| 인계 재현 성공률 | 성공 환경 수/검증 시도 수 | 측정 후 목표 설정 | 정적 검사만 된 경우 제외 |
| 중복 외부 POST | 동일 요청 재시도 후 중복 생성 수 | 0건 | idempotency |
| 사용자 개입 횟수 | 승인·자료입력 등 사람 단계 수 | 측정·비교 | 자동화보다 안전 우선 |
| 토큰/실행비용 | 작업별 모델·도구 비용 | 사용자 승인 한도 이내 | 실행 이외 외부 과금 포함 |

## F. 3종 벤치마크

- **Baseline A:** 사람이 동일한 문서와 공개 매물 화면에서 체크리스트 수행.
- **Baseline B:** 같은 자료를 범용 LLM 채팅에 넣고 추천/실사/협상 초안을 요청(단, 직접 API 수행 능력 없는 조건임을 명시).
- **Treatment C:** 우리 Agent+API+검증 도구.
- 동일한 사전 정의된 시나리오, 증거와 정답 데이터 사용. 조사자와 별도의 검토자가 가능한 한 독립 검토.
- 매출 증가/실제 거래율/구매 만족도는 샌드박스·합성 데이터에서 추정하지 않고 실사용자 파일럿 이후 측정.

## G. 장애·보안 회귀(반드시 통과)

- 악성 ZIP의 `../` 경로 압축 해제 차단, 링크·압축 폭탄 제한, 파일 크기 상한.
- 권한 없는 구매자가 소스 파일 다운로드 불가능.
- LLM 응답으로 인증·승인 조건 우회 불가능.
- 플랫폼 HTTP 429/500/timeout에서 상태 이중 생성 방지.
- 에이전트 작업 실패·취소·재시도 후 원상복구·감사 기록.
- `is_demo` 플래그가 API·DB·UI·리포트에서 일관성 유지.
- 과금 호출: 유료 모델 연결 기본 off, 비용 상한 넘어갈 때 실패/승인.

## I. 완료 기준

- P0 모든 테스트 통과, P1은 실제 구현 후 수행한 것만 별도 실측.
- 하나 이상의 E2E 완료 로그와 실행 증거 보관.
- 2개 코드베이스 간 v1 OpenAPI 계약 테스트 성공.
- 실제 금전 거래를 실행하지 않았음을 명확히 표시.
- 평가 자료는 화면 출력 과다 없이 파일로 저장.
- 코드·기능 상태를 과장하지 않고 미구현/실패를 함께 보고.
